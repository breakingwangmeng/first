# writing-plans

计划要细到"一个没品味、没判断力、没项目背景、讨厌写测试的初级工程师"也能照做。

## 任务粒度标准

- 每个任务 **2-5 分钟**可完成。
- 每个任务包含：**精确文件路径**、**完整代码**（或足够具体的伪代码）、**验证步骤**。
- 验证步骤必须可执行：跑哪条命令、看什么输出、断言什么结果。

## 结构

每个任务按下列模板写：

```markdown
## Task N: <一句话描述>

**文件**: `<path/to/file>`

**改动**: 具体做什么

**验证**: 
- 运行 `<command>`
- 预期输出 `<expected>`
```

## 原则

- 顺序执行：任务按依赖排序，无并行歧义。
- YAGNI：只拆已签字范围内的活。
- 测试先行：行为类任务先写测试再写实现，任务里写明测试文件路径。
- 任务完成后可独立验证，不依赖后续任务。

## 产出

更新 `openspec/changes/<name>/tasks.md`，每项带 checkbox：

```markdown
- [ ] 1.1 在 `src/theme.ts` 建立主题常量（验证：`tsc --noEmit` 通过）
```

## 反模式

- 任务写成"实现登录功能"这种无法验证的大块。
- 任务不写文件路径，靠执行者猜。
- 计划里塞进范围外的"顺手优化"。

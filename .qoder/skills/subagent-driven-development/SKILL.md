# subagent-driven-development

把"写代码"交给干净上下文的子代理，主对话保留全部项目上下文做审查。

## 模式

```
主对话（保上下文）          子代理（干净上下文）
─────────────────          ─────────────────
写 tasks.md        ──派发──> 任务 1：TDD 实现
审查任务 1 产出    <──报告── 返回验证证据
审查任务 2 产出    ──派发──> 任务 2：TDD 实现
...                          ...
整体 review        ──派发──> spec-reviewer 对账
```

## 派发要求

每次派发子代理，任务描述必须包含：

1. 当前任务的 tasks.md 原文（只给这一条，不给整个计划）。
2. 相关 spec 场景（scenario 原文）。
3. 精确文件路径与验证命令。
4. 返回格式要求：验证输出摘要 + 改动文件列表。

## 两阶段审查

1. **逐任务审查**：每个子代理返回后，主对话检查 spec 符合度与验证证据。
2. **整体审查**：全部完成后，派发 `spec-reviewer` 子代理做完整对账（见 `.qoder/agents/spec-reviewer.md`）。

## 何时用 / 不用

- 用：任务边界清晰、多任务可独立验证、主对话上下文紧张。
- 不用：任务间强耦合、需要全局视野的探索性重构。

## 反模式

- 把整个计划一次性甩给子代理（丢失逐任务审查）。
- 子代理返回"完成"但不带验证证据就放行。
- 主对话自己也写实现，与子代理改动冲突。

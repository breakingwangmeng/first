# verification-before-completion

证据优先。声称完成前，拿出能说服别人的验证证据。

## 验证清单

1. **测试全绿**：完整测试套件跑一遍，不是只跑改动相关的子集。
2. **验收对照**：逐条对照 proposal 的验收标准，每项给出证据（输出摘要、截图、文件位置）。
3. **边界实测**：手动触发一次边界/异常路径，确认行为符合 spec 场景。
4. **回归检查**：确认改动没破坏既有能力（跑相关测试 + 快速冒烟）。
5. **残留检查**：无调试代码、无临时代码、无未处理的 TODO（或已登记）。

## 证据要求

- 证据可复现：说"通过"要附上命令与输出摘要。
- 失败就报告失败：验证不过关时，如实说明卡在哪，禁止含糊其辞。

## 反模式

- 用"应该没问题"代替实际验证。
- 只贴绿色测试截图却不说明验收标准覆盖情况。
- 跳过失联验收标准的确认（"这条不重要就没验"）。

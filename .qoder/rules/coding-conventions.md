# Coding Conventions

## 命名

- 变量 / 函数 / 目录：语义化英文命名，禁止拼音、禁止无意义缩写。
- 目录与文件：kebab-case（如 `user-service.ts`）。
- 常量：UPPER_SNAKE_CASE；类型 / 接口：PascalCase；变量 / 函数：camelCase。
- 布尔变量：以 `is` / `has` / `can` 开头。

## 注释

- 注释解释"为什么"，不解释"做什么"（代码本身已经说明）。
- 每个公共 API / 导出函数必须有简短说明注释。
- 禁止注释掉的死代码提交进仓库，删除而不是注释。

## 错误处理

- 禁止吞异常：捕获后要么处理、要么包装后抛出。
- 错误信息必须包含足够的定位上下文（参数、标识符）。
- 边界条件显式处理，禁止依赖"恰好不会发生"。

## 函数设计

- 单一职责：一个函数只做一件事，长度超过 40 行考虑拆分。
- 参数超过 4 个考虑封装成对象。
- 禁止魔法数字 / 魔法字符串，提取为具名常量。

## 依赖与抽象

- YAGNI：不做没要求的事，不搞预防性抽象。
- DRY：重复 3 次以上才考虑抽取公共函数。
- 新增依赖前先检查是否已有等价能力，并说明引入理由。
